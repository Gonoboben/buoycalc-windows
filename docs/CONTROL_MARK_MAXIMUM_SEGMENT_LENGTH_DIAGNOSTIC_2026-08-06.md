# Контрольная отметка: максимальная длина расчётного сегмента

Дата: 2026-08-06  
Issue: #271

## Контекст

После Issue #268 и PR #270 расчётная линия сегментируется с фиксированным целевым шагом `0,20 м` без ограничения общего количества сегментов.

Действующее правило расчётного ядра:

```text
segmentCount = max(1, ceil(itemLength / 0.20))
segmentLength = itemLength / segmentCount
```

Для каждого положительного участка линии математически должно выполняться:

```text
0 < segmentLength <= 0.20 м
```

Небольшое превышение возможно только как эффект представления `double`, поэтому диагностическая граница использует абсолютный числовой допуск `1e-9 м`.

## Цель

Добавить независимую диагностическую строку, подтверждающую соблюдение выбранного пространственного шага во всех сформированных `SegmentCalculationRow`.

```text
CheckName: Максимальная длина расчётного сегмента
```

## Расчёт диагностических значений

```text
maximumSegmentLengthM = max(SegmentLengthM)
excessiveSegmentCount = count(SegmentLengthM > 0.20 + 1e-9)
```

Для пустой коллекции сегментов:

```text
maximumSegmentLengthM = NaN
excessiveSegmentCount = 0
```

Пустая коллекция проходит этот локальный инвариант. Наличие расчётной линии контролируется существующими проверками геометрии, длины и сегментации.

## Отображение

При наличии сегментов:

```text
max L=<значение> м; превышений <N>
```

При отсутствии сегментов:

```text
сегментов нет; превышений 0
```

Допуск:

```text
каждый L <= 0,20 м (+1e-9 м числового допуска)
```

## Severity

```text
OK    excessiveSegmentCount == 0
ERROR excessiveSegmentCount > 0
```

Новая строка может изменить только `EngineeringDiagnosticsResult.OverallSeverity`.

Она не меняет:

- `CalculationResult.Verdict`;
- `CalculationResult.MainRisk`;
- рассчитанные силы, натяжения, форму или координаты.

## Архитектурная граница

Production-изменение ограничивается файлом:

```text
Services/EngineeringDiagnostics.cs
```

Запрещено в рамках Issue #271:

- менять фиксированный шаг `0,20 м`;
- вводить лимит количества сегментов;
- вводить ограничение длины линии;
- добавлять preflight-блокировку;
- адаптивно укрупнять сегменты;
- усекать отчётные строки;
- менять UI-команды или поток расчёта;
- менять интерполяцию профиля, плотность, drag, вес, плавучесть, волну, натяжения или якорь;
- менять solver, gate, stores или selected-shape routing;
- менять 2D/PDF координаты;
- добавлять 3D.

## Проверяемые сценарии

### 1. Длина участка 1,00 м

```text
segmentCount = 5
segmentLength = 0,20 м
result = OK
```

### 2. Длина участка 1,01 м

```text
segmentCount = 6
segmentLength ~= 0,168333 м
result = OK
```

### 3. Длина участка меньше 0,20 м

```text
segmentCount = 1
segmentLength = itemLength
result = OK
```

### 4. Искусственно повреждённый read model

```text
SegmentLengthM = 0,2001 м
result = ERROR
```

### 5. Сегментов нет

```text
result = OK для локального инварианта
```

Оба PR объединяются только после успешных проверок:

- `.NET Build`;
- `Selected Shape Consumer Scan`;
- `Report Store Consumer Scan`.
