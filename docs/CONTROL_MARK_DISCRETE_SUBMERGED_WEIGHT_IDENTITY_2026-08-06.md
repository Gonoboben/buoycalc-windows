# Контрольная отметка: тождество веса дискретных элементов в воде

Дата: 2026-08-06  
Issue: #323  
Область: инженерная диагностика рассчитанного read model

## 1. Контекст

Для дискретных элементов расчётный результат теперь публикует:

```text
SourceUnitWeightAirKg
SourceUnitVolumeM3
Count
WeightWaterKg
```

Действующее тождество:

```text
WeightWaterKg = Count × (SourceUnitWeightAirKg - ρeffective × SourceUnitVolumeM3)
```

Для буя, прибора и якоря `Count = 1`. Для соединителя используется опубликованное нормализованное количество строки.

Участки линии не входят в эту проверку. Они используют подписанный погонный вес в воде и уже имеют отдельную проверку сохранения веса между элементными и сегментными строками.

## 2. Цель

Добавить одну diagnostic-only строку:

```text
Согласованность исходных масс/объёмов и веса в воде
```

Проверяются строки:

```text
Kind != "Линия"
```

Для каждой строки локально вычисляются:

```text
expected = Count × (SourceUnitWeightAirKg - ρeffective × SourceUnitVolumeM3)
absoluteResidual = abs(WeightWaterKg - expected)
relativeResidual = absoluteResidual / max(1, abs(expected))
```

`Count` берётся напрямую из `ElementCalculationRow`. Диагностика не применяет к нему `Math.Max`, не исправляет и не заменяет опубликованное значение.

## 3. Нарушение

Строка считается несогласованной, если:

- `Count < 0`;
- масса, объём, эффективная плотность, опубликованный или ожидаемый вес неконечны;
- абсолютная или относительная невязка неконечна;
- `relativeResidual > 1e-6`.

Физическая допустимость знаков исходных масс и объёмов контролируется отдельной диагностикой Issue #319. Эта строка проверяет именно сохранение формулы.

## 4. Отображение

```text
max Δm=<максимальная абсолютная невязка> кг;
max relative=<максимальная относительная невязка>;
нарушений <N>;
строк <C>
```

Для пустой коллекции:

```text
дискретных строк нет; локальный инвариант не применяется
```

## 5. Статус

```text
OK      — C > 0 и N = 0
ERROR   — N > 0
WARNING — C = 0
```

Отсутствие дискретных строк не объявляется локальной числовой ошибкой, но означает отсутствие ожидаемой системной границы буя/якоря. Точное наличие буя и валидность якоря контролируются отдельными строками.

## 6. Сохранение поведения

Не изменять:

- `WeightWaterKg`;
- `WeightInWaterKg`;
- исходные массу и объём;
- `Count` и масштабирование соединителей;
- эффективную плотность;
- плавучесть, drag и силы;
- натяжения, MBL, WLL и резервы;
- якорную модель;
- подписанный погонный вес линии;
- сегментацию 0,20 м без лимита числа сегментов;
- форму и solver;
- `CalculationResult.Verdict`, `MainRisk` и `Checks`;
- gate и selected shape;
- 2D и PDF-координаты;
- project JSON/DTO;
- XAML, команды и версию;
- 3D-область.

## 7. Допустимый production diff

Только:

```text
Services/EngineeringDiagnostics.cs
```

Отчёт меняется только через существующую таблицу инженерной диагностики.
