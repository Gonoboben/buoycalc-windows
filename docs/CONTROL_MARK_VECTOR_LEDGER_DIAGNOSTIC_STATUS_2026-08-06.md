# Контрольная отметка: статус векторной ведомости в инженерной диагностике

Дата: 2026-08-06
Issue: #211
Scope: documentation only

## Причина

`EngineeringDiagnostics` до сих пор описывает векторную ведомость как незавершённый solver-каркас:

```text
Это ещё не результат итерационного solver.
Вертикальная реакция пока не распределяется через контакт/грунт.
каркас собран; реакции не решены
требуется итерационный solver
WARNING
```

Текущая архитектурная граница уже установлена иначе.

`MooringVectorBalance` является проверочной ведомостью:

```text
- собирает внешние силовые члены;
- вычисляет требуемые реакции как R = -ΣF;
- показывает контрольный запас удержания по Rx;
- не решает опорные реакции, контакт с грунтом или равновесную геометрию.
```

Следовательно, `IsSolved=false` является намеренной характеристикой read model, а не отказом расчёта.

## Проблема severity

Текущая строка `Полный баланс всей постановки` всегда получает `WARNING` при `IsSolved=false`.

Поскольку `IsSolved` намеренно всегда false, общий статус `EngineeringDiagnosticsResult.OverallSeverity` не может стать `OK`, даже если:

```text
- геометрия сошлась;
- запасы достаточны;
- базовая нагрузка согласована с векторной ведомостью;
- инженерных ошибок нет.
```

Это ложное предупреждение.

## Точные production-правки

### Требуемая реакция Rx

Примечание заменить на:

```text
Требуемое значение для замыкания ΣFx=0; не является решённой реакцией опоры.
```

В отображаемом значении использовать:

```text
контрольный запас удержания
```

### Требуемая реакция Rz

Примечание заменить на:

```text
Требуемое значение для замыкания ΣFz=0; контактная/грунтовая модель в этой ведомости не решается.
```

### Статус ведомости

Название:

```text
Ведомость требуемых реакций
```

Значение:

```text
ведомость сформирована; показаны требуемые реакции
```

Допуск/граница:

```text
проверочная ведомость; не решение равновесия
```

Severity:

```text
INFO
```

`vectorBalance.MethodNote` сохраняется без изменения.

### Основной запас якоря

Название диагностической строки привести к уже принятому названию:

```text
Запас удержания якоря по базовой горизонтальной нагрузке
```

## Влияние на общий статус

После исправления информационная граница векторной ведомости не создаёт `WARNING` сама по себе.

`OverallSeverity` продолжает определяться существующими реальными проверками:

```text
- ERROR: инженерная ошибка или несогласованность;
- WARNING: несходимость/предупреждение предварительной модели;
- OK: ошибок и предупреждений нет.
```

Новая проверка согласованности `HorizontalForceN ↔ SumExternalFxN`, добавленная в Issue #208, остаётся без изменений и продолжает выдавать `ERROR` при расхождении.
