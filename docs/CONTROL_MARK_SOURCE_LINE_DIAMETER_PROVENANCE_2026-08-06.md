# Контрольная отметка: provenance исходного диаметра участка линии

Дата: 2026-08-06  
Issue: #315  
Область: расчётный read model и инженерная диагностика диаметра линии

## 1. Контекст

Активный участок линии получает диаметр из:

```text
RopePreset.DiameterMm
```

Расчёт использует это значение только через производную площадь сопротивления:

```text
A элемента = max(0, LengthM) × DiameterMm / 1000
A сегмента = SegmentLengthM × DiameterMm / 1000
```

`ElementCalculationRow` не сохраняет сам диаметр. Поэтому downstream-проверка видит только площадь:

- отрицательный диаметр проявляется как отрицательная площадь;
- нулевой диаметр выглядит как допустимая нулевая площадь;
- точное исходное значение и причина отсутствуют.

Для активной распределённой линии диаметр должен быть конечным и строго положительным.

Это правило не распространяется на `WeightWaterKgM`: погонный вес в воде может быть отрицательным для плавучей линии и не должен автоматически ограничиваться снизу нулём.

## 2. Выбранная граница результата

В `ElementCalculationRow` добавляется поле:

```text
SourceDiameterMm
```

Семантика:

```text
ProjectedAreaM2  — действующая производная расчётная площадь
SourceDiameterMm — точное конечное значение RopePreset.DiameterMm
```

Заполнение:

```text
активная строка линии => RopePreset.DiameterMm
соединитель           => 0
прибор                 => 0
буй                    => 0
якорь                  => 0
```

Новое поле является provenance расчётного входа. Оно не заменяет площадь и не участвует в существующих формулах.

## 3. Последовательность production-изменений

### Шаг A — result boundary

Отдельный behavior-preserving PR:

1. добавить `SourceDiameterMm` в конец `ElementCalculationRow`;
2. передать исходный диаметр только для строк линии;
3. передать `0` для остальных строк;
4. не добавлять потребителей и не менять вывод.

Допустимый production-файл:

```text
Models/EngineeringModels.cs
```

### Шаг B — инженерная диагностика

Отдельный diagnostic-only PR добавляет строку:

```text
Положительные исходные диаметры участков линии
```

Проверяются только:

```text
ElementRows, где Kind == "Линия"
```

Нарушение:

```text
SourceDiameterMm неконечен или <= 0
```

Отображение:

```text
min Dисх=<минимум или нет данных> мм;
неположительных/неконечных <N>;
участков <C>
```

Допуск:

```text
каждый Dисх > 0 и конечен
```

Статус:

```text
OK      — C > 0 и N = 0
ERROR   — N > 0
WARNING — C = 0
```

## 4. Разделение ответственности

Новая диагностика проверяет сам исходный геометрический параметр линии.

Она не заменяет существующие проверки:

- неотрицательной элементной и сегментной площади;
- неотрицательного `Cd`;
- рассчитанных сил сопротивления;
- согласованности сегментной и элементной силы линии.

Нулевая площадь остаётся допустимой для строк, намеренно не участвующих в drag, но нулевой диаметр активной линии получает отдельный `ERROR`.

## 5. Сохранение поведения

Не изменять:

- `RopePreset.DiameterMm`;
- формулы и значения `ProjectedAreaM2`;
- формулу drag;
- длины и сегментацию 0,20 м без лимита числа сегментов;
- профиль течения, плотность и интерполяцию;
- вес линии и знак `WeightWaterKgM`;
- силы, натяжения, слабое звено и резервы;
- якорную модель;
- `CalculationResult.Verdict`, `MainRisk` и `Checks`;
- solver, gate и selected shape;
- 2D и PDF-координаты;
- project JSON/DTO;
- XAML, команды и версию;
- 3D-область.

## 6. Отчёт

Result-boundary PR не меняет отчёт.

После diagnostic-only PR диаметр появляется только в существующей таблице инженерной диагностики. Основные таблицы продолжают показывать действующие расчётные площади.

## 7. Проверки перед merge

Каждый PR допускается к merge только после успешных:

- `.NET Build`;
- `Selected Shape Consumer Scan`;
- `Report Store Consumer Scan`.
