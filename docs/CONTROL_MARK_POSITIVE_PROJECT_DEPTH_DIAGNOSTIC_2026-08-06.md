# Контрольная отметка: положительная проектная глубина

Дата: 2026-08-06  
Issue: #274

## Контекст

Окончательная граница расчётного ввода удаляет `NaN` и infinity, но не исправляет конечные значения по физическому диапазону.

Поэтому `EnvironmentInput.DepthM` может содержать ноль или отрицательное число.

Существующие расчётные ветви обрабатывают такое значение неодинаково:

- сегментная глубина ограничивается диапазоном `0 .. max(0, DepthM)`;
- проверка `lineLength >= DepthM` может формально пройти при отрицательной глубине;
- оценочный снос использует исходный знак `DepthM`;
- инженерная диагностика создаёт локальное `depthM = max(0, DepthM)` и теряет исходный знак в последующих геометрических строках.

Это не должно исправляться скрытым clamping в рамках стабилизации. Неверное исходное значение должно быть показано отдельной диагностикой.

## Цель

Добавить строку:

```text
CheckName: Положительная проектная глубина
```

Она использует исходное значение:

```text
environment.DepthM
```

а не локально ограниченное значение `depthM`.

## Отображение

```text
Value: Depth=<исходное значение> м
Tolerance: Depth > 0 и конечна
```

Формат значения:

```text
Depth={environment.DepthM:0.####} м
```

## Severity

```text
OK    double.IsFinite(environment.DepthM) && environment.DepthM > 0
ERROR otherwise
```

Хотя входная граница уже не должна пропускать неконечные значения, finite-проверка остаётся частью локального инженерного инварианта.

## Пустые и граничные сценарии

### Положительная глубина

```text
Depth = 380 м
result = OK
```

### Нулевая глубина

```text
Depth = 0 м
result = ERROR
```

### Отрицательная глубина

```text
Depth = -10 м
result = ERROR
```

### Неконечная глубина в искусственно повреждённом read model

```text
Depth = NaN / Infinity
result = ERROR
```

## Архитектурная граница

Production-изменение ограничивается:

```text
Services/EngineeringDiagnostics.cs
```

Новая строка может изменить только:

```text
EngineeringDiagnosticsResult.Rows
EngineeringDiagnosticsResult.OverallSeverity
EngineeringDiagnosticsResult.Summary
```

Она не изменяет:

- `EnvironmentInput`;
- `CalculationResult.Verdict`;
- `CalculationResult.MainRisk`;
- входные строки UI;
- сохранённый проект;
- результаты расчётного ядра;
- координаты формы.

## Запрещённые изменения

В рамках Issue #274 запрещено:

- нормализовать или ограничивать `DepthM`;
- подставлять значение по умолчанию;
- блокировать команду расчёта;
- менять сегментную глубину;
- менять профиль течения или плотность;
- менять drag, волну, вес, плавучесть, натяжение или якорь;
- менять оценочный снос;
- менять solver, gate, stores или selected-shape routing;
- менять 2D/PDF координаты;
- менять JSON/DTO, XAML или команды;
- добавлять 3D.

## Порядок строки

Строка размещается в начальной группе входных физических инвариантов рядом с проверкой положительной эффективной плотности воды и до геометрических проверок формы.

Сначала документационный PR, затем отдельный production PR.

- `.NET Build`;
