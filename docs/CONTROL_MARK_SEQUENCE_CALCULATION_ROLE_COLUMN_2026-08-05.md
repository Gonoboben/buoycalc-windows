# Контрольная отметка: столбец расчётной роли последовательности

Дата: 2026-08-05
Issue: #193
Scope: documentation only

## Причина

Раздел технического отчёта `Позиционная модель последовательности по s` выводит столбец с заголовком `Роль в solver`.

Текущие значения столбца уже являются пользовательской классификацией участия элемента в расчёте:

```text
Буй    — верхний граничный узел.
Якорь  — нижний граничный узел.
Линия  — распределённые сегменты формы и натяжений.
Прочие — дискретная нагрузка по s в натяжениях и кандидатной форме.
```

Заголовок смешивает русский текст с внутренним термином `solver`. Для инженерного отчёта точнее использовать нейтральное название `Расчётная роль`.

## Разрешённая production-правка

В `Services/TechnicalReportMarkdownMovedSections.cs` заменить только Markdown-заголовок:

```diff
- Роль в solver
+ Расчётная роль
```

## Сохраняемая внутренняя граница

Свойство `MooringSequencePositionRow.SolverRole` в этом шаге не переименовывается.

Причины:

- пользователь видит заголовок и значения, а не имя свойства;
- текущее имя является внутренним контрактом read model;
- переименование создаст лишний model/DTO churn без изменения поведения;
- значения свойства уже корректно описывают расчётную роль.

## Инварианты

```text
- значения строк не меняются;
- порядок и количество строк не меняются;
- столбцы, кроме одного заголовка, не меняются;
- единицы и формат 0.#### не меняются;
- Escape(...) и Markdown-разметка строк не меняются;
- MooringSequencePositionRow и SolverRole не переименовываются;
- расчёты, solver, stores и selected shape не меняются;
- 2D и источник PDF-схемы не меняются;
- JSON, DTO, XAML, команды и версия приложения не меняются;
- 3D не добавляется.
```

## Safety gate

Production PR с однострочной правкой сливается только после зелёных:

```text
.NET Build
Selected Shape Consumer Scan
Report Store Consumer Scan
```
