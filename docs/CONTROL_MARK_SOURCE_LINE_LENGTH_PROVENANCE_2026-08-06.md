# Контрольная отметка: provenance исходной длины участка линии

Дата: 2026-08-06  
Issue: #305  
Область: расчётный read model и инженерная диагностика длины линии

## 1. Контекст

Активный участок линии передаёт конечное значение:

```text
AssemblyItemInput.LengthM
```

Расчётное ядро использует локально нормализованную длину:

```text
calculationLengthM = max(0, input.LengthM)
```

Эта нормализация участвует в:

- общей длине линии;
- весе линии;
- площади сопротивления;
- сегментации;
- форме X/Z.

`ElementCalculationRow.LengthM` хранит только нормализованное значение. Поэтому исходные `-5 м` и `0 м` downstream выглядят одинаково как `0 м`, и диагностика не может определить причину.

## 2. Выбранная граница результата

В `ElementCalculationRow` добавляется поле:

```text
SourceLengthM
```

Семантика:

```text
LengthM       — действующая нормализованная расчётная длина
SourceLengthM — точное конечное значение, полученное из AssemblyItemInput
```

Заполнение:

```text
активная строка линии => AssemblyItemInput.LengthM
соединитель           => 0
прибор                 => 0
буй                    => 0
якорь                  => 0
```

Новая property является provenance расчётного входа. Она не заменяет `LengthM` и не используется существующими формулами.

## 3. Последовательность production-изменений

### Шаг A — result boundary

Отдельный behavior-preserving PR:

1. добавить `SourceLengthM` в конец `ElementCalculationRow`;
2. передать исходную длину только для строк линии;
3. передать `0` для буя, якоря, соединителей и приборов;
4. не добавлять потребителей и не менять вывод.

Допустимый production-файл:

```text
Models/EngineeringModels.cs
```

### Шаг B — инженерная диагностика

Отдельный diagnostic-only PR добавляет строку:

```text
Положительные исходные длины участков линии
```

Проверяются только:

```text
ElementRows, где Kind == "Линия"
```

Нарушение:

```text
SourceLengthM неконечна или <= 0
```

Отображение:

```text
min Lисх=<минимум или нет данных> м;
неположительных/неконечных <N>;
участков <C>
```

Допуск:

```text
каждая Lисх > 0 и конечна
```

Статус:

```text
OK      — C > 0 и N = 0
ERROR   — N > 0
WARNING — C = 0
```

Отсутствие строк линии не исправляется автоматически и не заменяет существующие проверки общей длины, сегментов и формы.

Допустимый production-файл:

```text
Services/EngineeringDiagnostics.cs
```

## 4. Сохранение поведения

Не изменять:

- `Math.Max(0, LengthM)`;
- значения `ElementCalculationRow.LengthM`;
- общую длину и вес линии;
- площадь сопротивления и силы;
- шаг сегментации 0,20 м и решение без лимита сегментов;
- профиль течения и плотность;
- натяжения, слабое звено и резервы;
- якорную модель;
- `CalculationResult.Verdict`, `MainRisk` и `Checks`;
- solver, gate и selected shape;
- 2D и PDF-координаты;
- project JSON/DTO;
- XAML, команды и версию;
- 3D-область.

## 5. Отчёт

Result-boundary PR не меняет отчёт.

После diagnostic-only PR исходная длина появляется только в существующей таблице инженерной диагностики. Основные таблицы элементов и сегментов продолжают показывать действующие расчётные значения.

## 6. Проверки перед merge

Каждый PR допускается к merge только после успешных:

- `.NET Build`;
- `Selected Shape Consumer Scan`;
- `Report Store Consumer Scan`.
