# Контрольная отметка: provenance исходных масс и объёмов

Дата: 2026-08-06  
Issue: #319  
Область: расчётный read model и инженерная диагностика дискретных элементов

## 1. Контекст

`ElementCalculationRow.WeightWaterKg` хранит производный вес элемента в воде.

Для дискретного элемента используется выражение:

```text
mв воде = mв воздухе - ρ × V
```

Для соединителя результат дополнительно умножается на число элементов.

Исходные `mв воздухе` и `V` downstream не сохраняются. Из-за этого физически недопустимая отрицательная масса может компенсироваться отрицательным объёмом и дать положительный, внешне правдоподобный вес в воде.

Затронуты:

- буй;
- соединитель;
- прибор;
- якорь.

Участок линии исключён из этой границы: он использует подписанный погонный вес в воде `WeightWaterKgM`. Отрицательное значение допустимо для плавучей линии.

## 2. Выбранная граница результата

В конец `ElementCalculationRow` добавляются поля:

```text
SourceUnitWeightAirKg
SourceUnitVolumeM3
```

Семантика:

- значения относятся к одной физической единице элемента;
- для соединителя `Count` отдельно задаёт количество;
- действующий `WeightWaterKg` остаётся итоговым значением строки с учётом количества;
- для линии оба поля равны нулю и не используются.

Заполнение:

```text
Буй         => BuoyInput.WeightKg, BuoyInput.VolumeM3
Соединитель => ConnectorPreset.WeightAirKg, ConnectorPreset.VolumeM3
Прибор      => PayloadWeightAirKg, PayloadVolumeM3
Якорь       => AnchorInput.WeightAirKg, AnchorInput.VolumeM3
Линия       => 0, 0
```

## 3. Последовательность production-изменений

### Шаг A — result boundary

Отдельный behavior-preserving PR:

1. добавляет два поля в `ElementCalculationRow`;
2. заполняет их исходными значениями;
3. не добавляет потребителей;
4. не меняет отчёт или диагностику.

Допустимый файл:

```text
Models/EngineeringModels.cs
```

### Шаг B — диагностика

Отдельный diagnostic-only PR добавляет две строки.

#### 3.1. Неотрицательные исходные массы и объёмы дискретных элементов

Проверяются строки:

```text
Kind != "Линия"
```

Нарушение массы:

```text
SourceUnitWeightAirKg неконечна или < 0
```

Нарушение объёма:

```text
SourceUnitVolumeM3 неконечен или < 0
```

Нулевые значения допускаются для идеализированных точечных элементов или намеренно неучтённого водоизмещения.

Отображение:

```text
min mвозд=<минимум> кг;
нарушений массы <M>;
min V=<минимум> м³;
нарушений объёма <V>;
строк <C>
```

Статус:

```text
OK    — M = 0 и V = 0
ERROR — иначе
```

#### 3.2. Положительный исходный объём буя

Проверяются строки:

```text
Kind == "Буй"
```

Требование:

```text
ровно одна строка буя;
SourceUnitVolumeM3 > 0 и конечен
```

Статус:

```text
OK      — одна валидная строка
ERROR   — строка есть, но число строк или объём недопустимы
WARNING — строка буя отсутствует
```

## 4. Разделение ответственности

Новые поля не участвуют в физике и не дублируют расчёт.

Диагностика исходных значений дополняет, но не заменяет:

- проверку положительной плавучести;
- состояние буя;
- положительный вес якоря в воде;
- запас удержания якоря;
- согласованность веса линии и сегментов.

Для линии не вводится ограничение `WeightWaterKgM ≥ 0`.

## 5. Сохранение поведения

Не изменять:

- `WeightInWaterKg`;
- масштабирование соединителей по `Count`;
- `WeightWaterKg` существующих строк;
- плавучесть и вес буя;
- якорный вес в воде и удержание;
- профиль, drag и силы;
- натяжения, MBL, WLL и резервы;
- сегментацию 0,20 м без лимита числа сегментов;
- форму и solver;
- `CalculationResult.Verdict`, `MainRisk` и `Checks`;
- gate и selected shape;
- 2D и PDF-координаты;
- project JSON/DTO;
- XAML, команды и версию;
- 3D-область.

## 6. Отчёт

Result-boundary PR не меняет отчёт.

После diagnostic-only PR исходные масса и объём появляются только в существующей таблице инженерной диагностики.

## 7. Проверки перед merge

Каждый PR допускается к merge только после успешных:

- `.NET Build`;
- `Selected Shape Consumer Scan`;
- `Report Store Consumer Scan`.
